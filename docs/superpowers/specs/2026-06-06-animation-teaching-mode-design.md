# 蜥蜴动画教学模式（渐进渲染实验室）— 设计文档

> 日期：2026-06-06
> 状态：已与用户确认设计方向，待写实现计划
> 决策摘要：独立轻量教学渲染器 · 渲染阶段递进（13 步，含收尾"参数化"）· 每阶段配示范提示词 · 实时动画+播放控制 · **每一步均支持鼠标牵引** · **纯隔离，无"对照真机"增强**

## 1. 背景与目标

本项目（reptile-Gaming）的蜥蜴是**纯程序化 Canvas 2D 动画**：脊椎链 FK + 蛇形波、4 腿 2 骨段 IK、身体轮廓描边、头部、皮肤花纹、视野锥、战斗动作，全部实时计算（生产实现见 `client/js/lizard-renderer.js`，约 1713 行）。

教学模式的目标：用一个**独立单页**，把"从一个移动的点 → 逐阶段叠加/精化 → 逼真蜥蜴动画 → 参数化可调"的过程切成 13 个**可切换查看**的阶段，每一步都是**实时动画**且**可用鼠标牵引蜥蜴移动**，并配一张「示范提示词 + 技术讲解 + 对应真实代码」卡片，演示"如何用提示词把动画逐步完善"的全过程。开场以项目**创世提示词**（`prompt.txt`）作为缘起背景。

## 2. 范围与隔离边界

### 2.1 在范围内
- 一个可直接在浏览器打开的独立页面（无需登录、无需服务端）。
- 13 个递进阶段（第 0–11 步为渲染阶段，第 12 步为"参数化"收尾），可点击跳转 / 上一步 / 下一步 / 自动演进。
- 每一步均为实时动画（蜥蜴会爬动/摆动），支持播放/暂停/调速。
- **每一步都支持鼠标牵引**：在画布上按下/拖动时，蜥蜴（或第 0 步的锚点）跟随鼠标移动；松开后回到自动漫游。
- 每一步的提示词卡片（示范提示词、技术讲解、对应真实代码位置）。
- 第 12 步"参数化"：提供一小组参数滑块（受限集合，非任意编辑器），实时改变完整蜥蜴的体型/配色/花纹/节数等。

### 2.2 隔离原则（硬约束）
- 全部为**新增文件**；**不修改、不导入** `lizard-renderer.js`、`battle-animator.js`、`lizard-battle-adapter.js` 或任何游戏/服务端代码。
- 教学渲染器自带一套**精简、可读、带注释**的物理/IK 实现（不是复制生产代码）。
- 参数取值**忠实对齐**真实渲染器的概念与量级（参考 `lizard_params001.json` 与 `docs/05-sync-rules.md` 的 render_params 基础值），做到"代码独立而行为神似"。
- 明确**不做**"对照真实 LizardRenderer 并排展示"的增强（用户已否决，保持纯隔离）。

### 2.3 不做什么（YAGNI）
- 不接登录 / 服务端 / 真实战斗引擎数据。
- 第 12 步"参数化"只暴露**固定一小组**滑块（如体型、头部、肢体粗细、配色色相、花纹类型、脊椎节数），**不做**任意字段的自由编辑器或预设的保存/加载。
- 不接真实音效。
- 不改动现有任何页面或样式文件。

## 4. 核心引擎：TeachingRenderer

### 4.1 状态模型
渲染器自持一份精简模型状态：
- `spine`：节点数组 `[{x,y}, …]`（节数由当前阶段配置决定，6 → 12 → 更长）。
- `legs`：4 条腿 `{hipIndex, side, foot, plant, stepping, phase}`（启用 IK 后才参与）。
- `head`：朝向角、视觉头角。
- `time` / `serpentinePhase` / `gaitPhase`：动画相位。
- `target`：当前移动锚点。**鼠标牵引激活时 = 鼠标位置；否则 = 自动漫游目标。**
- `params`：当前生效的外观参数（默认取 sample-creature；第 12 步由滑块覆盖）。

### 4.2 按阶段配置驱动（核心机制）
每个阶段是一个**声明式配置**（定义在 `teaching-stages.js`），描述"这一步开启了什么 + 用什么参数"：

```js
// 概念结构（teaching-stages.js 中每一项）
{
  key: 'spine_ik',
  spineNodes: 16,
  features: {
    legs: true, head: false, body: false, bodyCurve: false,
    collision: false, serpentine: false, skin: false,
    spikes: false, vision: false, battle: false, params: false
  },
  prompt: '…示范提示词…',
  explanation: '…技术讲解…',
  codeRef: '_solveIK / _updateLegs'
}
```

渲染器内部把每种能力实现为一个**带开关的层函数**（`updateXxx` / `drawXxx`），主循环按当前阶段的 `features` 决定跑哪些 update、画哪些 draw，并按 `spineNodes`/`params` 配置模型。

- 多数能力一旦开启就保持开启（视觉上呈"逐步完善"）；
- 但 `spineNodes` 等配置可在阶段间变化（支持"短脊椎→长脊椎"这类**重配置**而非纯叠加）；
- `collision`、`serpentine` 等为独立开关，对应各自的教学步骤。

### 4.3 对外接口
```js
class TeachingRenderer {
  constructor(canvas, sampleCreature) {}
  applyStage(stageConfig) {}   // 按阶段配置重建/重配模型（节数变化时重建脊椎并复位）
  setParams(partialParams) {}  // 第 12 步：滑块实时覆盖外观参数
  play() {} / pause() {} / setSpeed(mult) {}
  reset() {}                   // 复位模型（切步骤/重播时干净复位，避免状态污染）
  destroy() {}                 // 解绑鼠标事件、停止循环
  // 内部：_loop() 每帧按 features 依次 update 再依次 draw
  //       _bindMouse() 处理按下/拖动/松开 → 设置 target 跟随鼠标
}
```

- 自带 `requestAnimationFrame` 循环；`document.hidden` 时暂停。
- "切换查看第 N 步" = `applyStage(stages[N])`；"自动演进" = 定时推进到下一阶段。
- 鼠标牵引在构造时绑定一次，对所有阶段生效（包含第 0 步的裸锚点）。

### 4.4 精简但忠实的算法要点
- **鼠标牵引 / 锚点**：按下或移动鼠标时 target = 光标位置，松开后恢复自动漫游（对应真实 `_bindEvents` + `setExternalMoveTarget` 思路）。
- 脊椎 FK：头节点跟随 target，后续节点按固定段长跟随前一节点。
- IK 腿：2 骨段解析解（与 `_solveIK` 同法），对角步态分组，落脚点 + 迈步插值。
- 头部 / 身体轮廓：沿脊椎法线取左右点描成闭合路径填充；头形 + 独立朝向。
- 体型曲线：段长与半宽随归一化位置变化（颈/肩/腹/胯/尾），形成锥形。
- 防自碰撞：节点间最小间距约束 + 弯折角约束（对应 `_resolveBodyCollisions`/`_enforceAngleConstraints`）。
- 蛇形波：沿脊椎索引叠加正弦横向偏移（量级对齐真实 `SERPENTINE_*`）。
- 皮肤花纹 / 背刺 / 脚部 / 视野锥 / 光点 / 战斗动作：各自一层，按开关叠加。

## 5. 教学步骤（13 步：0–11 渲染阶段 + 12 参数化）

| # | key | 阶段 | 该步新增/变化 | 教的概念 | 对应真实代码 |
|---|-----|------|--------------|---------|------------|
| 0 | anchor | 移动锚点 | 一个会漫游、可鼠标牵引的目标点 | 一切从"会动的点"开始 | `_computeAITarget` / `_bindEvents` |
| 1 | spine_short | 短脊椎链(6节) | 6 节 FK 链跟随锚点 | 正向运动学 / 跟随 | `_initSpine` / `_updateSpine` |
| 2 | spine_long | 长脊椎链(12节) | 节数增至 12，链更柔顺 | 节数 → 柔顺度 | `SPINE_NODE_COUNT` |
| 3 | spine_ik | 更长脊椎 + IK 腿部 | 节数再增 + 4 腿 2 骨段 IK + 对角步态 | 反向运动学 / 步态 | `_solveIK` / `_updateLegs` |
| 4 | skin_outline | 头部 + 身体轮廓 | 头形 + 左右描边填充剪影（等宽） | 头身分离 / 轮廓生成 | `_drawHead` / `_traceBodyPath` / `_drawBody` |
| 5 | bodyform | 体型曲线 | 段长/半宽按位置变化 → 锥形体型 | 体节参数化 | `_segmentLengthAt` / `_bodyWidthAt` |
| 6 | collision | 防止自碰撞 | 最小间距 + 弯折角约束 | 自碰撞 / 角约束 | `_resolveBodyCollisions` / `_enforceAngleConstraints` |
| 7 | serpentine | 蛇形摆动 | 脊椎横向正弦波动 | serpentine 波 | `_updateSpine`(波部分) / `SERPENTINE_*` |
| 8 | skin_pattern | 皮肤花纹 | 渐变配色 + 花纹（body_seed） | 程序化外观 | `_generateSkinColors` / `_drawPattern` |
| 9 | details | 背刺与脚部细节 | 脊背刺、脚趾细节 | 细节装饰层 | `_drawSpines` / `_drawFoot` |
| 10 | vision | 视野锥 + 光点 | FOV 锥、感知光点 | 感知可视化 | `_drawVisionCone` / `_drawLightDots` / `_findNearestDotInFOV` |
| 11 | battle | 战斗动作 | 一次扑咬/突进 + 命中特效 | 动作驱动 + 特效 | `setExternalMoveTarget` / `_applyTestEffect` / `triggerSkillTest` |
| 12 | params | 参数化 | 完整形态 + 一组实时参数滑块 | render_params → 外观映射 | `applyRenderParams` / `applyHiddenGene` |

设计要点：
- 第 1→2→3 步通过**改变脊椎节数**演示"链越长越柔顺"，是"重配置"而非新增图层。
- 第 4 步先用**等宽**轮廓把骨架"包上皮"，第 5 步再用体型曲线把剪影精化为锥形——先有形、再精化。
- 第 6 步把自碰撞/角约束单独成步，直观展示"加约束前会自穿插，加约束后顺滑"。
- 第 12 步"参数化"建立在完整蜥蜴之上，滑块覆盖 `params`，实时 `setParams()` 重绘；可保留触发战斗动作的入口。

每步配套卡片三块：
1. **示范提示词**：面向教学的"要让 AI 加上这一层，你会这样提示…"（为每阶段编写，贴合真实管线）。
2. **技术讲解**：本步新增/变化了什么、核心概念。
3. **对应真实代码**：指向 `client/js/lizard-renderer.js` 的相应方法名（把教学连回真实工程）。

步骤数据全部声明在 `teaching-stages.js`，与渲染器解耦。

## 6. 页面布局与交互

```
┌─────────────────────────────────────────────────────────┐
│  顶部：标题 + "创世提示词"(prompt.txt 摘录, 可折叠)        │
├──────────────────────────────┬──────────────────────────┤
│                              │  当前步骤卡片              │
│   大画布(实时动画 / 鼠标牵引) │  ① 示范提示词              │
│                              │  ② 技术讲解                │
│      （第12步右侧叠加         │  ③ 对应真实代码            │
│        参数滑块面板）         │                          │
├──────────────────────────────┴──────────────────────────┤
│  步进时间轴: ⓪…⑪⑫  (可点击跳转 / 高亮当前)               │
│  控制: ⏮上一步 ⏭下一步 │ ▶︎播放/⏸暂停 │ 速度 │ ⏩自动演进 │
└─────────────────────────────────────────────────────────┘
```

交互语义：
- **鼠标牵引（每一步）**：在画布上按下并拖动 → 蜥蜴/锚点跟随光标；松开 → 恢复自动漫游。画布上给出轻提示"拖动可牵引"。
- **▶︎ 动画播放**：当前步骤的蜥蜴持续动起来（爬动/摆尾/迈步）。
- **⏩ 自动演进**：每隔数秒自动跳到下一阶段，幻灯片式从锚点演进到参数化；到末步停止或循环。
- **参数面板（仅第 12 步）**：一组滑块（体型 bodyScale、头部 headScale、肢体粗细 limbThickness、配色色相 bodyHue、花纹类型 patternType、脊椎节数 spineNodes 等），改变即 `setParams()` 实时重绘。
- 时间轴每个节点显示序号 + 阶段名；点击直接跳到该步。
- 键盘左右方向键 = 上一步/下一步（低成本增强）。
- 切步骤时按需复位画布，卡片内容随之更新。

## 7. 数据与样式

- `sample-creature.js`：固定一只蜥蜴的 `render_params` + `body_seed`（结构与服务端一致，数值写死），作为各步骤默认外观与第 12 步滑块的初值。
- 样式 `animation-lab.css`：自包含深色调，视觉与项目（如 `battle-debug.css`）一致但不复用其文件，避免耦合。
- 页面不引入任何现有 js/css；只引入 `teaching/` 下三个脚本 + `animation-lab.js`。

## 8. 验收标准

1. 直接用浏览器打开 `client/animation-lab.html` 即可运行，无需启动服务端、无需登录。
2. 13 个步骤均可点击切换，画面按阶段配置正确呈现（节数变化、特性开关均生效）。
3. **每一步**均可用鼠标按下/拖动牵引蜥蜴（或第 0 步的锚点）移动，松开恢复漫游。
4. 每步均为实时动画，播放/暂停/调速生效；自动演进能从第 0 步走到第 12 步。
5. 第 12 步参数滑块实时改变完整蜥蜴外观（体型/配色/花纹/节数等）。
6. 每步卡片正确显示示范提示词、讲解、对应真实代码方法名。
7. 顶部可展开查看创世提示词（prompt.txt 摘录）。
8. 全程未修改任何现有文件；`git status` 仅新增上述文件。
9. `node --check` 通过所有新增 .js；浏览器控制台无报错。

## 9. 风险与注意事项

- **教学版与真机的忠实度**：精简实现可能与生产细节有出入。对策：参数量级对齐、卡片"对应真实代码"明确指回真实方法，定位为"概念忠实的教学重建"而非逐像素复刻。
- **阶段状态污染 / 重配置**：脊椎节数在阶段间变化，`applyStage` 需在节数变化时重建脊椎并 `reset()` 干净复位，避免残留或索引越界（腿的 hipIndex 等需随节数重算）。
- **鼠标坐标换算**：需把鼠标事件坐标按画布缩放/偏移正确换算到内部坐标（注意 DPR、canvas 实际像素 vs CSS 像素）。
- **性能**：单画布 + 单只蜥蜴，rAF 负载低；注意 `document.hidden` 暂停以省电。
- **文件编码**：项目部分文档为 GBK（如 DEVLOG）。新增文件统一 UTF-8，避免乱码。
- **命名**：页面文件名暂定 `animation-lab.html`，若需更贴近"教学模式"可在实现前重命名（如 `animation-tutorial.html`）。
